Правила sing-box из любого сайта: rule-set для Hiddify и NekoBox

Клиенты на ядре sing-box — Hiddify, NekoBox, Karing, официальные приложения SFA/SFI/SFM — решают, что пускать через прокси, по правилам: списку доменов и сетей. NetRoute генерирует такой список в формате rule-set прямо со страницы сайта: открыли сайт, нажали «Анализировать», скачали .json — и подключили.

Что внутри файла

Rule-set в исходном формате (source) — это JSON с версией и списком правил. NetRoute пишет домены и сети двумя отдельными правилами: в sing-box условия внутри одного правила объединяются по «И», и правило с доменами и сетями вместе никогда бы не сработало.

{
  "version": 1,
  "rules": [
    { "domain_suffix": ["github.com", "githubusercontent.com"] },
    { "ip_cidr": ["140.82.112.0/20", "185.199.108.0/22", "2606:50c0::/32"] }
  ]
}
  • domain_suffix — домен и все его поддомены. NetRoute сворачивает список: если найдены api.github.com и github.com, остаётся только github.com, а www. отбрасывается.
  • ip_cidr — агрегированные сети, IPv4 и IPv6 вместе: те же маршруты, что NetRoute выдал бы для роутера, включая режимы BGP Prefix и Full AS.
  • version: 1 — формат sing-box 1.8 и новее; все последующие версии читают его без изменений.

Что понадобится

  • Клиент на sing-box: Hiddify, NekoBox, Karing, приложения SFA/SFI/SFM или сам sing-box на компьютере или роутере
  • Рабочее подключение к прокси (VLESS, Hysteria, Shadowsocks, WireGuard — любое, у которого в конфиге есть outbound)
  • Расширение NetRoute в Chrome

Шаг 1. Сгенерируйте rule-set в NetRoute

  1. Откройте нужный сайт в Chrome и обновите страницу, чтобы сниффер поймал фоновые запросы
  2. Запустите NetRoute
  3. В списке форматов выберите sing-box / Hiddify / NekoBox в группе «Прокси-клиенты»
  4. Поля «Шлюз» и «Устройство» для этого формата не нужны
  5. Нажмите Анализировать
  6. На вкладке Домены снимите галочки с лишнего — счётчики, рекламные сети, чужие CDN; правила пересчитаются сразу
  7. Скачайте файл: он называется по сайту, например github_com_rules.json
Сети нужны не всегда. Клиент сопоставляет домен ещё до резолва, поэтому для обычных сайтов хватает правила domain_suffix. Сети пригодятся, когда приложение ходит на серверы по IP, минуя DNS — так делают мессенджеры и игры. Если хотите только домены, выключите IPv4 и IPv6 в параметрах скана — правило ip_cidr исчезнет.

Шаг 2. Подключите файл в sing-box

Локальный файл рядом с конфигом:

{
  "route": {
    "rule_set": [
      {
        "type": "local",
        "tag": "netroute",
        "format": "source",
        "path": "github_com_rules.json"
      }
    ],
    "rules": [
      { "rule_set": "netroute", "outbound": "proxy" }
    ],
    "final": "direct"
  }
}

Файл по ссылке — удобно для телефонов и для обновления без правки конфига. Положите .json в репозиторий на GitHub, приватный gist или на свой сервер и укажите прямую ссылку на сырой файл:

{
  "type": "remote",
  "tag": "netroute",
  "format": "source",
  "url": "https://raw.githubusercontent.com/you/rules/main/github_com_rules.json",
  "download_detour": "proxy",
  "update_interval": "24h"
}

outbound должен совпадать с тегом вашего прокси-outbound (часто proxy, select или имя сервера). download_detour скачивает сам список через прокси — полезно, если GitHub у вас недоступен напрямую.

Hiddify, NekoBox, Karing. Графические клиенты принимают либо ссылку на rule-set в настройках маршрутизации, либо полный JSON-конфиг sing-box с блоком route выше. Название пункта меняется от версии к версии — ищите «Rule set», «Routing» или «Пользовательские правила». Если клиент даёт только поле для URL, опубликуйте файл по ссылке, как во втором примере.

Шаг 3. Проверьте

Синтаксис конфига вместе с rule-set:

sing-box check -c config.json

Запустите клиент и откройте сайт. При "log": {"level": "info"} в журнале sing-box видно, какое правило сработало:

INFO [1234567890] inbound/tun[tun-in]: inbound connection to github.com:443
INFO [1234567890] router: match[0] rule_set=netroute => proxy

Если сайт должен открываться через прокси, а в логе => direct — правило не совпало: проверьте, что домен есть в domain_suffix и что правило стоит выше правил с final или geosite-исключениями.

Скомпилированный rule-set (.srs)

Для больших списков sing-box читает бинарный формат быстрее. Скомпилируйте файл NetRoute один раз:

sing-box rule-set compile github_com_rules.json
# → github_com_rules.srs

В конфиге укажите "format": "binary" и путь к .srs. Для десятка сайтов это не нужно — исходный JSON читается мгновенно.

Частые проблемы

decode rule-set: unsupported version

Клиент на sing-box старше 1.8 не знает формата rule-set. Обновите клиент: NetRoute уже пишет минимальную version: 1, ниже опускаться некуда.

Правило не срабатывает на поддомене

domain_suffix покрывает поддомены, но только того домена, который в списке. Если сайт тянет данные с другого домена — откройте вкладку Домены в NetRoute: он там есть, если страница к нему обращалась. Пройдитесь по сайту перед сканом — войдите в аккаунт, откройте видео, — тогда сниффер увидит и ленивые запросы.

Трафик по IP идёт мимо прокси

Правило ip_cidr сравнивает адрес назначения уже после резолва. Если в клиенте включён sniff и домен определился — сработает правило по домену; если нет — адрес должен попасть в одну из сетей. Для сервисов с меняющимися IP включите в NetRoute Оптимизация маршрутов → BGP Prefix: вместо отдельных адресов в ip_cidr попадут анонсируемые префиксы.

Один rule-set на несколько сайтов

Используйте массовое сканирование: вставьте список URL или доменов — NetRoute соберёт один rule-set на всех, файл будет называться bulk_N_rules.json.

DNS и утечки

В отличие от маршрутов на роутере, правило по домену срабатывает до резолва: sing-box видит имя из SNI или HTTP-запроса и отправляет соединение в outbound, не спрашивая системный DNS. Но сам DNS-запрос браузера всё равно уходит — и если он идёт к провайдеру, провайдер видит имена сайтов.

  • Направьте DNS в прокси: в секции dns.servers задайте сервер с "detour": "proxy" для доменов из правила, например через dns.rules с тем же rule_set: netroute.
  • Включите "sniff": true на inbound — тогда соединения по IP тоже получат домен и попадут под domain_suffix.
  • В браузере отключите собственный DNS-over-HTTPS или укажите в нём резолвер, идущий через туннель, иначе Chrome резолвит имена в обход клиента.

Проверка: dnsleaktest.com при включённом клиенте должен показывать резолвер прокси, а не провайдера.

Пример конфигурационного файла

Готовый шаблон. Замените примеры доменов и сетей выводом NetRoute для ваших сайтов.

  • singbox-rules.json — rule-set в исходном формате с правилами domain_suffix и ip_cidr

{
  "version": 1,
  "rules": [
    {
      "domain_suffix": [
        "avatars.githubusercontent.com",
        "github.com",
        "github.githubassets.com"
      ]
    },
    {
      "ip_cidr": [
        "140.82.112.0/20",
        "185.199.108.0/22",
        "2606:50c0::/32"
      ]
    }
  ]
}

Подсказка: текстовые форматы скачиваются с шапкой-комментарием. Снимите галочку «Включать комментарии в экспортируемые файлы» в настройках NetRoute, чтобы получить только правила; JSON-форматы комментариев не содержат.
