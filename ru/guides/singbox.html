Rule-set sing-box из любого сайта: домены и сети для Hiddify и sing-box

sing-box и клиенты на его ядре — официальные приложения sing-box, Hiddify, NekoBox — решают, что пускать через прокси, по правилам: спискам доменов и сетей, которые с версии 1.8.0 оформляются как rule-set. NetRoute собирает такой rule-set прямо со страницы сайта: открыли сайт, нажали «Анализировать сайт», скачали .json.

Что внутри файла

Rule-set в исходном формате (source) — это JSON с полями version и rules. NetRoute пишет домены и сети двумя отдельными правилами: по документации sing-box условия внутри одного правила объединяются логическим «И», и одно правило с доменами и сетями срабатывало бы только при совпадении и того, и другого.

{
  "version": 1,
  "rules": [
    { "domain_suffix": ["github.com", "githubusercontent.com"] },
    { "ip_cidr": ["140.82.112.0/20", "185.199.108.0/22", "2606:50c0::/32"] }
  ]
}
  • domain_suffix — совпадение по суффиксу домена: сам домен и все его поддомены. NetRoute сворачивает список: если на странице найдены api.github.com и github.com, остаётся github.com; префикс www. отбрасывается. В список попадают все домены скана, в том числе те, что не удалось разрешить в IP.
  • ip_cidr — совпадение по сети. Это те же агрегированные сети, которые NetRoute выдал бы маршрутами для роутера, IPv4 и IPv6 вместе; правило есть, если хотя бы один домен разрешился в адрес.
  • version: 1 — первая версия формата, появившаяся в sing-box 1.8.0.

Что понадобится

  • sing-box 1.8.0 или новее: сам sing-box на компьютере, сервере или роутере либо официальные приложения sing-box for Android, sing-box for Apple platforms, sing-box for Desktop
  • или Hiddify — клиент на ядре sing-box, который по README принимает конфигурации в формате sing-box (Android, iOS, Windows, macOS, Linux)
  • Рабочий outbound прокси в конфиге — протокол любой
  • Расширение NetRoute в Chrome
NekoBox для Android тоже работает на ядре sing-box, но, по его README, из подписок берёт только узлы, а правила маршрутизации игнорирует. Rule-set туда можно принести только внутри полного конфига sing-box.

Шаг 1. Сгенерируйте rule-set в NetRoute

  1. Откройте нужный сайт в Chrome и обновите страницу, чтобы сниффер расширения увидел фоновые запросы
  2. Запустите NetRoute
  3. В списке Целевая ОС выберите sing-box / Hiddify / NekoBox — группа «Прокси-клиенты»
  4. Поля IP шлюза и Интерфейс на этот формат не влияют
  5. Нажмите Анализировать сайт
  6. На вкладке Домены снимите галочки с лишнего — счётчики, рекламные сети, чужие CDN; правила пересчитаются сразу
  7. Нажмите Скачать: файл называется по сайту, например github_com_rules.json
Про сети. Правило ip_cidr попадает в файл всегда, когда есть разрешённые адреса, и домену оно не мешает. Нужен список из одних доменов — удалите второе правило из файла. Чтобы сетей было меньше, выберите в Режим роутов вариант IPv4 Only: правило останется без IPv6-префиксов.

Шаг 2. Опишите файл в конфиге sing-box

Локальный файл рядом с конфигом. format можно не указывать, если путь заканчивается на .json или .srs; с версии 1.10.0 sing-box перечитывает файл сам при изменении.

{
  "route": {
    "rule_set": [
      {
        "type": "local",
        "tag": "netroute",
        "format": "source",
        "path": "github_com_rules.json"
      }
    ],
    "rules": [
      { "rule_set": "netroute", "action": "route", "outbound": "proxy" }
    ],
    "final": "direct"
  }
}
  • outbound — тег вашего прокси-outbound. Запись "action": "route" обязательна начиная с sing-box 1.11.0: старое поле outbound прямо в правиле там объявлено устаревшим.
  • final — outbound по умолчанию для всего, что не совпало ни с одним правилом; direct даёт классический split tunneling.

Файл по ссылке. Положите .json в репозиторий на GitHub или на свой сервер и укажите прямую ссылку на сырой файл; по умолчанию sing-box обновляет его раз в сутки (update_interval = 1d):

{
  "type": "remote",
  "tag": "netroute",
  "format": "source",
  "url": "https://raw.githubusercontent.com/you/rules/main/github_com_rules.json",
  "update_interval": "1d"
}

Если ссылка должна скачиваться через прокси: до sing-box 1.13 для этого служило поле download_detour с тегом outbound, с 1.14.0 оно объявлено устаревшим в пользу http_client, а в 1.16.0 удалено.

Hiddify. Приложение принимает конфигурации в формате sing-box — добавьте в такой конфиг блок route выше вместе с вашим outbound и импортируйте его как профиль. Как именно импортировать профиль в вашей версии Hiddify, смотрите в документации приложения.

Шаг 3. Проверьте

Синтаксис конфига вместе с rule-set:

sing-box check -c config.json

Затем запустите sing-box и откройте сайт. Если он открывается через прокси, а остальные сайты идут напрямую — правило работает. Если нет, пройдите по списку частых проблем ниже.

Скомпилированный rule-set (.srs)

Для больших списков sing-box предлагает бинарный формат. Скомпилируйте файл NetRoute командой из документации:

sing-box rule-set compile github_com_rules.json
# → github_com_rules.srs

В конфиге укажите "format": "binary" и путь к .srs. Для десятка сайтов это не обязательно.

Частые проблемы

sing-box не принимает файл

Rule-set появился в sing-box 1.8.0; более старые версии и клиенты на них формат не знают. NetRoute пишет минимальную version: 1 — все последующие версии её читают.

Правило не срабатывает на поддомене

domain_suffix покрывает поддомены только тех доменов, что есть в списке. Если сайт тянет данные с другого домена, его должно быть видно на вкладке Домены в NetRoute. Пройдитесь по сайту перед сканом — войдите в аккаунт, откройте видео — тогда сниффер расширения увидит и отложенные запросы.

Соединения по IP идут мимо прокси

Правило по домену требует, чтобы sing-box знал имя назначения. Для этого служит сниффинг: он достаёт имя из поля Host в HTTP и из Server Name в TLS и QUIC. С sing-box 1.11.0 сниффинг включается правилом с "action": "sniff" в route.rules (старое поле sniff у inbound объявлено устаревшим и удалено в 1.13.0). Соединения без имени сравниваются по правилу ip_cidr — для сервисов с меняющимися адресами включите в настройках NetRoute Оптимизация маршрутов → BGP Prefix: в сети попадут анонсируемые префиксы, а не отдельные адреса.

Один rule-set на несколько сайтов

Нажмите URL list рядом с кнопкой анализа и вставьте список сайтов — NetRoute соберёт один rule-set на всех, файл будет называться bulk_N_rules.json.

DNS и утечки

Правило по домену не меняет того, как браузер разрешает имена: DNS-запрос к github.com всё равно уходит на тот резолвер, который настроен в системе или в самом браузере, и если это резолвер провайдера — провайдер видит имена сайтов.

  • В sing-box правила DNS умеют ссылаться на тот же rule-set: правило dns.rules с "rule_set": "netroute", "action": "route" и server отправит запросы к этим доменам на выбранный DNS-сервер. Чтобы сам сервер ходил через прокси, задайте у него detour с тегом outbound — это поле из общих параметров подключения (Dial Fields); серверы в новом формате ("type": "https" и другие) появились в sing-box 1.12.0.
  • В Chrome отключите «Использовать безопасный DNS» или укажите в нём резолвер, которому доверяете: собственный DNS-over-HTTPS браузера работает в обход системного резолвера — подробнее в разделе Troubleshooting проекта.

Проверка: dnsleaktest.com при включённом клиенте должен показывать резолвер прокси, а не провайдера.

Пример конфигурационного файла

Готовый шаблон. Замените примеры доменов и сетей выводом NetRoute для ваших сайтов.

  • singbox-rules.json — rule-set в исходном формате с правилами domain_suffix и ip_cidr

{
  "version": 1,
  "rules": [
    {
      "domain_suffix": [
        "avatars.githubusercontent.com",
        "github.com",
        "github.githubassets.com"
      ]
    },
    {
      "ip_cidr": [
        "140.82.112.0/20",
        "185.199.108.0/22",
        "2606:50c0::/32"
      ]
    }
  ]
}

Подсказка: текстовые форматы скачиваются с шапкой-комментарием. Снимите галочку «Включать комментарии в экспортируемые файлы» в настройках NetRoute, чтобы получить только правила; JSON-форматы комментариев не содержат.
