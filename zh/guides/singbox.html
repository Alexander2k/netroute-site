从任意网站生成 sing-box rule-set：Hiddify 与 sing-box 的域名和网段

更新于 2026-10-17 · NetRoute 版本 4.1.4

sing-box 及基于它构建的客户端 — 官方 sing-box 应用、Hiddify、NekoBox — 依靠规则决定哪些流量走代理：规则是域名和网段的列表，自 1.8.0 版起打包为 rule-set。NetRoute 可直接从网站生成这样的 rule-set：打开网站，点击「分析网站」，下载 .json 即可。

文件内容

源格式（source）的 rule-set 是一个带有 version 和 rules 的 JSON 文档。NetRoute 将域名和网段写成两条独立的规则：按照 sing-box 文档，同一条规则内的条件以逻辑「与」组合，若把域名和网段放在同一条规则中，则只有两者同时匹配时才会命中。

{
  "version": 1,
  "rules": [
    { "domain_suffix": ["github.com", "githubusercontent.com"] },
    { "ip_cidr": ["140.82.112.0/20", "185.199.108.0/22", "2606:50c0::/32"] }
  ]
}
  • domain_suffix — 域名后缀匹配：域名本身及其所有子域名。NetRoute 会折叠列表：当页面同时使用 api.github.com 和 github.com 时，只保留 github.com；www. 前缀会被去掉。扫描到的所有域名都会列出，包括未能解析出 IP 的域名。
  • ip_cidr — 网段匹配。这些就是 NetRoute 为路由器输出路由时所用的同一批聚合网段，IPv4 和 IPv6 一起；只要至少有一个域名解析出了地址，这条规则就会存在。
  • version: 1 — 该格式的第一个版本，自 sing-box 1.8.0 引入。

准备工作

  • sing-box 1.8.0 或更新版本：电脑、服务器或路由器上的 sing-box 二进制程序，或官方应用 sing-box for Android、sing-box for Apple platforms、sing-box for Desktop
  • 或 Hiddify — 基于 sing-box 内核的客户端，按其 README 的说明接受 sing-box 格式的配置（Android、iOS、Windows、macOS、Linux）
  • 配置中有一个可用的代理 outbound — 协议不限
  • Chrome 中已安装 NetRoute 扩展
NekoBox for Android 同样运行在 sing-box 内核上，但按其 README 的说明，它只从订阅中获取节点，忽略路由规则。rule-set 只有包含在完整的 sing-box 配置中才能进入该应用。

步骤 1. 在 NetRoute 中生成 rule-set

  1. 在 Chrome 中打开目标网站并刷新页面，让扩展的嗅探器看到后台请求
  2. 启动 NetRoute
  3. 在 「目标系统」 中选择 sing-box / Hiddify / NekoBox — 位于「代理客户端」分组
  4. 「网关 IP」 和 「网络设备」 字段不影响此格式
  5. 点击 「分析网站」
  6. 在 「域名列表」 标签页中取消勾选不需要的项 — 统计计数器、广告网络、第三方 CDN；规则会立即更新
  7. 点击 「下载」：文件以网站命名，例如 github_com_rules.json
关于网段。只要有已解析的地址，ip_cidr 规则就总会出现在文件中，它不会妨碍域名规则。只想要域名 — 从文件中删除第二条规则。想要更少的网段 — 在 「路由模式」 中选择 IPv4 Only：规则中将不再包含 IPv6 前缀。

步骤 2. 在 sing-box 配置中描述该文件

与配置放在一起的本地文件。当路径以 .json 或 .srs 结尾时可以省略 format；自 1.10.0 起，文件变化时 sing-box 会自行重新加载。

{
  "route": {
    "rule_set": [
      {
        "type": "local",
        "tag": "netroute",
        "format": "source",
        "path": "github_com_rules.json"
      }
    ],
    "rules": [
      { "rule_set": "netroute", "action": "route", "outbound": "proxy" }
    ],
    "final": "direct"
  }
}
  • outbound — 你的代理 outbound 的 tag。自 sing-box 1.11.0 起必须写 "action": "route"：直接写在规则中的旧 outbound 字段在该版本已被弃用。
  • final — 所有未匹配任何规则的流量的默认 outbound；direct 即经典的分流。

通过 URL 引用的文件。将 .json 放到 GitHub 仓库或自己的服务器上，并给出原始文件的直接链接；默认情况下 sing-box 每天刷新一次（update_interval = 1d）：

{
  "type": "remote",
  "tag": "netroute",
  "format": "source",
  "url": "https://raw.githubusercontent.com/you/rules/main/github_com_rules.json",
  "update_interval": "1d"
}

如果该链接必须通过代理下载：在 sing-box 1.13 及之前由带 outbound tag 的 download_detour 字段完成；1.14.0 将其弃用并改用 http_client，1.16.0 将其移除。

Hiddify。该应用接受 sing-box 格式的配置 — 把上面的 route 块连同你的 outbound 一起加入这样的配置，并将其作为配置文件（profile）导入。你所用 Hiddify 版本中具体如何导入配置文件，请参阅应用的文档。

步骤 3. 检查

检查配置连同 rule-set 的语法：

sing-box check -c config.json

然后启动 sing-box 并打开网站。如果该网站通过代理打开，而其他网站直连 — 规则生效。如果没有，请查看下面的常见问题。

编译后的 rule-set（.srs）

对于大型列表，sing-box 提供二进制格式。使用文档中的命令编译 NetRoute 文件：

sing-box rule-set compile github_com_rules.json
# → github_com_rules.srs

在配置中设置 "format": "binary" 和 .srs 的路径。对于十几个网站来说没有必要这样做。

常见问题

sing-box 拒绝该文件

rule-set 在 sing-box 1.8.0 中出现；更早的版本以及基于它们构建的客户端不认识这种格式。NetRoute 写入最低的 version: 1 — 之后的每个版本都能读取。

规则没有匹配到子域名

domain_suffix 只覆盖列表中域名的子域名。如果网站从另一个域名拉取数据，它应该出现在 NetRoute 的 「域名列表」 标签页中。扫描前先在网站上浏览一遍 — 登录、打开一个视频 — 让扩展的嗅探器也能看到延迟发出的请求。

按 IP 发起的连接绕过了代理

域名规则需要 sing-box 知道目标名称。这正是嗅探的用途：它从 HTTP 的 Host 字段以及 TLS 和 QUIC 的 Server Name 中获取名称。自 sing-box 1.11.0 起，嗅探通过 route.rules 中带 "action": "sniff" 的规则启用（inbound 上旧的 sniff 字段已弃用，并在 1.13.0 中移除）。没有名称的连接由 ip_cidr 规则匹配 — 对于地址经常变化的服务，请在 NetRoute 选项中启用 「路由优化 → BGP 前缀」：网段将变为公告的前缀而不是单个地址。

一个 rule-set 包含多个网站

点击分析按钮旁的 「URL 列表」 并粘贴网站列表 — NetRoute 会为所有网站生成一个 rule-set，文件名为 bulk_N_rules.json。

DNS 与泄漏

域名规则不会改变浏览器解析名称的方式：对 github.com 的 DNS 查询仍然发往系统或浏览器自身配置的解析器，若那是运营商的解析器，运营商就能看到网站的名称。

  • 在 sing-box 中，DNS 规则可以引用同一个 rule-set：一条带 "rule_set": "netroute"、"action": "route" 和 server 的 dns.rules 记录会把这些域名的查询发送到所选的 DNS 服务器。要让该服务器本身走代理，给它设置带 outbound tag 的 detour — 这是共享 Dial Fields 中的一个字段；新格式的服务器（"type": "https" 等）在 sing-box 1.12.0 中出现。
  • 在 Chrome 中关闭「使用安全 DNS」或将其指向你信任的解析器：浏览器自己的 DNS-over-HTTPS 会绕过系统解析器 — 参见项目的 Troubleshooting 部分。

检查：开启客户端后，dnsleaktest.com 应显示代理的解析器，而不是运营商的。

配置文件示例

可直接编辑的模板。将示例中的域名和网段替换为 NetRoute 为目标网站生成的输出。

  • singbox-rules.json — 源格式的 rule-set，包含 domain_suffix 和 ip_cidr 规则

{
  "version": 1,
  "rules": [
    {
      "domain_suffix": [
        "avatars.githubusercontent.com",
        "github.com",
        "github.githubassets.com"
      ]
    },
    {
      "ip_cidr": [
        "140.82.112.0/20",
        "185.199.108.0/22",
        "2606:50c0::/32"
      ]
    }
  ]
}

提示：文本格式下载时带有注释头。在 NetRoute 选项中取消勾选 「在导出文件中包含注释」 即可只保留规则；JSON 格式不含注释。
