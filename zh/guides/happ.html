从任意网站生成 Happ 路由配置文件

更新于 2026-10-17 · NetRoute 版本 4.1.4

Happ 是基于 Xray 内核的跨平台客户端，支持 Windows、macOS、Linux、iOS、Android 和 TV 平台。哪些流量走代理由路由配置文件（routing profile）决定：即域名和地址的列表。NetRoute 可从网站生成这样的 JSON 配置文件，它以 happ://routing/onadd/… 链接的形式进入应用。

文件内容

Happ 路由配置文件是一个 JSON 文档，包含 DNS 和 geo 文件设置以及六个列表：哪些走代理、哪些直连、哪些被屏蔽 — 域名和地址各自分开。NetRoute 填写代理列表，其余保持 Happ 默认接受的值：

{
  "Name": "NetRoute github.com",
  "GlobalProxy": "false",
  "RemoteDNSType": "DoH",
  "RemoteDNSDomain": "https://1.1.1.1/dns-query",
  "RemoteDNSIP": "1.1.1.1",
  "DomesticDNSType": "DoH",
  "DomesticDNSDomain": "https://77.88.8.8/dns-query",
  "DomesticDNSIP": "77.88.8.8",
  "Geoipurl": "",
  "Geositeurl": "",
  "LastUpdated": "1760572800",
  "DnsHosts": {},
  "RouteOrder": "block-proxy-direct",
  "DirectSites": [],
  "DirectIp": ["geoip:private"],
  "ProxySites": ["domain:github.com", "domain:githubusercontent.com"],
  "ProxyIp": ["140.82.112.0/20", "185.199.108.0/22", "2606:50c0::/32"],
  "BlockSites": [],
  "BlockIp": [],
  "DomainStrategy": "IPIfNonMatch",
  "FakeDNS": "false"
}

各字段的含义，按 Happ 文档：

  • GlobalProxy — 为 true 时所有流量默认走代理，为 false 时直连；同一个值也决定了所有未匹配任何规则的流量的出口。NetRoute 设为 false：只有列出的网站走代理。
  • ProxySites / ProxyIp — 走代理的域名和地址。域名写成 domain:name 形式 — 按 Xray 文档，这表示该域名及其所有子域名；列表已折叠，www. 已去掉。地址是 NetRoute 为路由器输出路由时所用的同一批聚合网段，IPv4 和 IPv6。
  • DirectSites / DirectIp 和 BlockSites / BlockIp — 直连和屏蔽；NetRoute 只把私有地址留为直连（geoip:private）。
  • RouteOrder — 规则的检查顺序：先屏蔽，再代理，最后直连。
  • DomainStrategy — Xray 策略：IPIfNonMatch 只在没有规则按名称匹配时才把域名解析为地址。
  • RemoteDNS* / DomesticDNS* — 分别用于走代理的网站和其余网站的 DNS；DoH 即 DNS-over-HTTPS。如需其他解析器，请在导入前修改文件中的值。
  • Geoipurl / Geositeurl — geoip.dat 和 geosite.dat 的链接；空值由 Happ 从其默认配置文件填充。
  • LastUpdated — Unix 格式的日期；当它大于之前的值时配置文件才会更新。NetRoute 写入生成时间。
  • DnsHosts — 手动的「域名: IP」映射，类似 hosts 文件；NetRoute 的配置文件中为空。

准备工作

  • 已添加服务器的 Happ 应用（Windows、macOS、Linux、iOS、Android、Android TV 或 Apple TV）
  • Chrome 中已安装 NetRoute 扩展
  • 一种对文件进行 base64 编码的方法 — 每个系统都有相应的命令，示例见下文

步骤 1. 在 NetRoute 中生成配置文件

  1. 在 Chrome 中打开目标网站并刷新页面，让扩展的嗅探器看到后台请求
  2. 启动 NetRoute
  3. 在 「目标系统」 中选择 Happ — 位于「代理客户端」分组
  4. 「网关 IP」 和 「网络设备」 字段不影响此格式
  5. 点击 「分析网站」
  6. 在 「域名列表」 标签页中取消勾选不需要的项 — 统计计数器、广告网络、第三方 CDN；配置文件会立即更新
  7. 点击 「下载」：文件以网站命名，例如 github_com_rules.json

步骤 2. 构造 happ://routing/… 链接

按 Happ 文档，配置文件通过链接添加，其中 {base64} 是转换为 base64 文本的 JSON 配置文件：

  • happ://routing/add/{base64} — 将配置文件添加到列表；
  • happ://routing/onadd/{base64} — 添加并立即激活，即使当前有另一个配置文件处于激活状态。

对下载的文件进行编码：

# Windows, PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("github_com_rules.json"))

# macOS
base64 -i github_com_rules.json

# Linux
base64 -w0 github_com_rules.json

在结果前面加上 happ://routing/onadd/ — 一整行，不含空格或换行。链接会很长；这是正常的。

请在本地编码文件 — 在线编码器会看到你的网站列表。NetRoute 计划内置「复制为 Happ 链接」按钮。

步骤 3. 将链接添加到 Happ

按 Happ 文档，链接可通过三种方式接收 — 从剪贴板复制、扫描二维码以及作为 deeplink：

  1. 将构造好的链接复制到剪贴板
  2. 打开 Happ，点击主屏幕右上角的 +
  3. 从剪贴板添加链接。传到手机上最简单的方式是以二维码传递或作为 deeplink 打开 — 系统会提示在 Happ 中打开
  4. 使用 onadd 时配置文件已处于激活状态；使用 add 时请在路由配置文件列表中选择它
  5. 重新连接：按文档说明，配置文件的更改在 Reconnect（重新连接）后生效

步骤 4. 检查

打开为其生成配置文件的网站 — 它应通过代理打开，而其他网站直连（GlobalProxy: false）。如果情况相反，请检查 Happ 中激活的是哪个路由配置文件，以及导入后是否已重新连接。

常见问题

链接不被接受

检查 base64 是否为不含换行的单行（在 Linux 上需要 -w0 参数），以及前面是否正好是 happ://routing/onadd/ 或 happ://routing/add/。

配置文件已添加但没有任何变化

Happ 在重新连接时应用更改后的配置文件。使用 add 链接时，还必须将该配置文件选为激活状态。

网站从其他域名拉取数据

它们应该出现在 NetRoute 的 「域名列表」 标签页中 — 扩展会从页面及其后台请求中收集域名。扫描前先在网站上浏览一遍（登录、打开一个视频），让延迟发出的请求也进入配置文件。多个网站放进一个配置文件 — 使用分析按钮旁的 「URL 列表」 按钮：文件名为 bulk_N_rules.json。

订阅中的配置文件

按 Happ 文档，JSON 订阅中严格只能包含 0 或 1 个路由配置文件，而配置文件链接可以放在 routing 头部或直接放在订阅正文中 — 向多台设备分发设置时很方便。

DNS 与泄漏

配置文件设置了两个 DNS 服务器：RemoteDNS 用于走代理的网站，DomesticDNS 用于其余网站 — 两者都通过 DNS-over-HTTPS（NetRoute 的文件中为 Cloudflare 和 Yandex）。如需其他解析器，请在编码前在 JSON 中修改。浏览器的查询仍然发往其自身配置的 DNS：在 Chrome 中关闭「使用安全 DNS」或将其指向你信任的解析器，否则 Chrome 会绕过客户端解析名称。

检查：开启 Happ 后，dnsleaktest.com 应显示配置文件中的解析器，而不是运营商的。

配置文件示例

可直接编辑的模板。将示例中的域名和网段替换为 NetRoute 为目标网站生成的输出。

  • happ-routing.json — 包含 ProxySites 和 ProxyIp 列表的 Happ 路由配置文件

{
  "Name": "NetRoute github.com",
  "GlobalProxy": "false",
  "RemoteDNSType": "DoH",
  "RemoteDNSDomain": "https://1.1.1.1/dns-query",
  "RemoteDNSIP": "1.1.1.1",
  "DomesticDNSType": "DoH",
  "DomesticDNSDomain": "https://77.88.8.8/dns-query",
  "DomesticDNSIP": "77.88.8.8",
  "Geoipurl": "",
  "Geositeurl": "",
  "LastUpdated": "1760572800",
  "DnsHosts": {},
  "RouteOrder": "block-proxy-direct",
  "DirectSites": [],
  "DirectIp": [
    "geoip:private"
  ],
  "ProxySites": [
    "domain:avatars.githubusercontent.com",
    "domain:github.com",
    "domain:github.githubassets.com"
  ],
  "ProxyIp": [
    "140.82.112.0/20",
    "185.199.108.0/22",
    "2606:50c0::/32"
  ],
  "BlockSites": [],
  "BlockIp": [],
  "DomainStrategy": "IPIfNonMatch",
  "FakeDNS": "false"
}

提示：文本格式下载时带有注释头。在 NetRoute 选项中取消勾选 「在导出文件中包含注释」 即可只保留规则；JSON 格式不含注释。
